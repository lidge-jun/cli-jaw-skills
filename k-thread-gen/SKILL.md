# K-Thread Generator

한국 커뮤니티(Threads/트위터/블라인드 등)에 올리는 **슬라이드형 포스트**를 생성하는 스킬.

## When to use (trigger phrases)

- "쓰레드 만들어줘" / "슬라이드로 만들어줘"
- "이거 포스트로 정리해줘" / "커뮤니티 글 써줘"
- "이 뉴스 쓰레드로" / "thread로 변환해줘"

---

## 1. 후킹 (MOST CRITICAL)

첫 슬라이드에서 스크롤을 멈추게 해야 한다.
후킹이 약하면 아무도 안 읽는다.
**후킹이 쓰레드의 80%다.**

### 어그로 공식 (강도순)

| Lv  | 패턴            | 예시                                    | 메커니즘               |
| --- | --------------- | --------------------------------------- | ---------------------- |
| 🔥🔥🔥 | **상식 부정**   | "맥 안 사도 됨"                         | 믿고 있던 걸 깨부숨    |
| 🔥🔥🔥 | **정보 격차**   | "이거 아직도 모르는 사람 많던데"        | 나만 모르나? 불안 자극 |
| 🔥🔥🔥 | **도발적 질문** | "아직도 돈 내고 써?"                    | 내가 호구인가? 자극    |
| 🔥🔥  | **숫자 + 반전** | "4줄 복붙했더니 설치 끝남"              | 기대보다 쉬운 반전     |
| 🔥🔥  | **대비/vs**     | "무조건 퇴사한다 vs 그래도 직장 다닌다" | 본능적 편가르기        |
| 🔥🔥  | **손해 회피**   | "이거 안 쓰면 매달 2만원씩 버림"        | 잃는 게 싫은 심리      |
| 🔥   | **현장감**      | "카페인데 맞은편 여자는..."             | 궁금증 유발            |
| 🔥   | **감정 폭발**   | "너무너무너무 잘한다"                   | 공감                   |

### 정보 격차 (Information Gap) 기법
사람은 "내가 모르는 게 있다"고 느끼면 반드시 클릭한다.

```
1단계: 결과를 먼저 보여줌 (구체적 숫자)
2단계: 방법은 감춤 (다음 슬라이드에)
3단계: 독자가 "어떻게?"를 스스로 물어보게 만듦

예시:
"윈도우에서 4줄 복붙으로 AI 비서 세팅 끝남
맥 없어도 됨
무료임"
→ 독자: "뭔데? 어떻게?" → 다음 슬라이드 넘김
```

### 클릭베이트 리라이트 공식
팩트는 유지하면서 어그로만 올리는 방법:

```
원본 → 리라이트 공식 → 결과

[평범한 사실]
→ [누구에게 해당?] + [뭘 몰랐는데?] + [결과가 어떻길래?]

❌ "CLI-JAW 윈도우 지원합니다"
→ 누가 몰랐는데? + 결과가?
✅ "맥 없어서 AI 코딩 못한다는 사람 아직도 있던데
윈도우에서 4줄이면 끝남"

❌ "올해 구글 딱 두번 샀어"
→ 결과가?
✅ "올해 구글 딱 두번 탔는데 수익률 보고 퇴사 고민 중"

❌ "새로운 팀원이 생겼습니다"
→ 반전?
✅ "신입 뽑았는데 월급 0원이고 24시간 일함"

❌ "차단걱정없고 세팅끝나는 오픈클로 공개합니다"
→ 누구에게 해당? + 뭘 몰랐는데?
✅ "아직도 오픈클로 쓰다가 밴 먹는 사람 있던데
밴 자체가 불가능한 구조가 있음"
```

### 후킹 체크리스트 (생성 후 반드시 수행)
첫 슬라이드를 이 기준으로 자체 검증. 하나라도 실패하면 **다시 써야 함**:
- [ ] 3초 안에 "뭔데?" 또는 "어떻게?" 반응이 나오는가?
- [ ] 구체적인 숫자가 있는가? (없으면 넣어라)
- [ ] 결과/반전이 암시되어 있는가? (다음 슬라이드를 안 넘길 이유가 없어야 함)
- [ ] "나도 해당되는 이야기"라고 느끼게 하는가? (타겟 독자가 명확한가)
- [ ] 첫 줄만 읽어도 주제가 파악되는가?

## 2. 말투 규칙

### ⚠️ 음슴체가 아니라 대화체다
**"~됨", "~임", "~했음" 같은 음슴체는 기본값이 아님.**
실제 커뮤니티 포스트는 **친구한테 말하듯** 쓴다.

```
❌ 음슴체 (딱딱함)
"설치 끝남"
"무료임"
"사용할 수 있음"

✅ 대화체 (자연스러움)
"설치 끝나"
"무료야"
"쓸 수 있어"
"너무 힘들어"
"해보면 될까?"
"의견을 구해보아~"
"모으자"
```

### 절대 원칙: 하나의 톤으로 밀어라
**한 쓰레드 안에서 톤을 섞지 말 것.**
반말이면 끝까지 반말. 존댓말이면 끝까지 존댓말.
ㅋㅋ 쓰다가 갑자기 "~합니다" 나오면 어색함.

```
❌ 톤 섞기 (금지)
"풀어주고 있습니다"  ← 존댓말
"골라서 쓸 수 있는 플랫폼이야"  ← 반말
"결과가 꽤 놀라운데요"  ← 존댓말
→ 한 사람이 쓴 것 같지 않음

✅ 대화체 반말로 밀기
"풀어주고 있어"
"골라서 쓸 수 있는 플랫폼이야"
"결과가 꽤 미쳤어"

✅ 존댓말로 밀기
"풀어주고 있습니다"
"골라서 쓸 수 있는 플랫폼입니다"
"결과가 꽤 놀랍습니다"
```

### 톤 선택 가이드

| 톤                     | 언제 쓰는가          | 어미 패턴                          |
| ---------------------- | -------------------- | ---------------------------------- |
| **대화체 반말** (기본) | 대부분의 포스트      | ~해, ~야, ~지, ~거든, ~인데, ~ㅋㅋ |
| **친근 반말**          | 팁 공유, 의견 구하기 | ~해봐, ~해보면 돼, ~구해보아~      |
| **건조 반말**          | 뉴스, 팩트 전달      | ~했다, ~라고 한다, ~밝혔다         |
| **직설 반말**          | 동기부여, 에세이     | ~이다, ~한다, ~했다                |
| **존댓말**             | 전문적 소개, 브랜드  | ~합니다, ~입니다, ~보여줍니다      |

**기본값**: 유저가 톤을 지정하지 않으면 **대화체 반말**

### 대화체 어미 패턴
```
일반:    ~해, ~야, ~지, ~인데, ~거든
설명:    ~인 거야, ~하는 건데, ~인듯
질문:    ~될까?, ~할까?, ~있나?
권유:    ~해봐, ~하자, ~모으자, ~구해보아~
감탄:    ~미쳤어, ~대박이야, ~ㅋㅋㅋ
공감:    ~힘들어, ~알지?, ~그렇지?
강조:    진짜, 너무너무, 개~
```

### 쉼표/말줄임 활용
```
,,, → 감정적 멈춤 ("학원강사인데,,,")
.. → 여운 ("만들고 싶다..")
~ → 부드러운 마무리 ("구해보아~")
! → 흥분 ("됐어요!!!")
```

### 핵심 원칙
- **줄바꿈 = 구두점**. 마침표 대신 줄바꿈
- **한 줄에 하나의 생각만**
- **친구한테 카톡 보내듯** 쓸 것. AI가 쓴 것 같으면 실패
- **번역체 금지**: "~에 대해", "~를 통해", "~함으로써" 사용 시 즉시 제거

### 이모지 규칙
- 제목이나 포인트에 1~2개 OK
- 본문 3줄에 1개 이하
- 결과 티징에 효과적: "결과는?🤣"
- 도배 = 촌스러움

## 3. 쓰레드 구조 (본문 + 댓글)

### ⚠️ 쓰레드는 하나의 글이 아니다
쓰레드 = **본문 1개** + **댓글로 이어 쓰기**
본문에 훅을 걸고, 세부 내용은 **자기 댓글에 1/ 2/ 3/ 형태로 달아 나가는 방식**이야.

```
[본문] ← 훅 + 핵심 요약. N / M 넘버링 포함
  └─ [댓글 1] ← 1/ 내용...
  └─ [댓글 2] ← 2/ 내용...
  └─ [댓글 3] ← 3/ 내용... (마지막: 출처, CTA)
```

### 본문 (= 1 / N)
- 훅이 들어가는 첫 게시물
- `N / M` 넘버링 포함 (예: `1 / 4`)
- 여기서 스크롤을 멈추게 만들어야 함
- "댓글에 이어서" 같은 유도 문구 가능
- **본문 구조**: 후킹 → 원인/배경 설명 → 사진/동영상 첨부. 본문에 링크 넣지 않음
- **본문에 링크 금지**: 본문에는 URL을 넣지 않는다. 대신 관련 사진이나 동영상을 첨부한다
- **출처 링크는 마지막 댓글에**: 링크는 마지막 댓글에만 배치
- **플레인 텍스트**: 마크다운 볼드(**), 이모지 도배 금지. 실제 커뮤니티에 그대로 붙여넣기 가능해야 함
- **영어 원문 우선**: 한국 뉴스 번역 기사가 아니라 영어 원문 기사/블로그를 1차 출처로 사용할 것. 검색 시 영어 키워드로 원문을 반드시 찾아서 링크. 한국어 기사만 있는 경우에만 한국어 링크 허용

### 댓글 (= 1/ 2/ 3/ ...)
- 본문에 대한 **자기 댓글**로 이어 씀
- 각 댓글 맨 위에 `1/`, `2/` 번호를 붙임
- 댓글 하나 = 하나의 포인트 or 단계

### 넘버링 규칙
```
본문: 1 / 4       ← 전체 슬라이드 수 포함
댓글: 1/           ← 댓글 내 서브 넘버링 (슬래시 뒤 공백 없음)
      2/
      3/
```

모든 내용에 넘버링이 필요한 건 아님 — 댓글이 1~2개면 번호 없이도 OK

### 역할

| 위치        | 어디에   | 역할       | 필수 요소                |
| ----------- | -------- | ---------- | ------------------------ |
| 1/N         | **본문** | **훅**     | 스크롤 멈추게 하는 한 줄 |
| 1/~(N-1)/   | **댓글** | **본문**   | 정보, 맥락, 세부 내용    |
| 마지막 댓글 | **댓글** | **마무리** | 요약, 의견, CTA, 출처    |

### 길이 가이드
- 짧은 소식: 본문만 (댓글 없음)
- 뉴스/의견: 본문 + 댓글 2~3개
- 가이드/리스트: 본문 + 댓글 4~7개
- 본문/댓글 각각 **최대 500자** (한국어 기준)
- 내용 없으면 억지로 안 늘림

### 출력 포맷
```
[본문]
[후킹 한 줄]

[원인/배경 2~3줄]

(사진/동영상 첨부)

1 / N

---

[댓글 1]
1/
[첫번째 포인트]

---

[댓글 2]
2/
[두번째 포인트]

---

[댓글 마지막]
[요약 or CTA]
[출처 링크]
```

### 플레인 텍스트 규칙
- 출력물은 커뮤니티에 그대로 복붙 가능해야 함
- 마크다운 문법 사용 금지: **, ##, - (리스트), > (인용) 등 쓰지 않음
- 이모지는 포인트 강조에 1~2개만 허용
- 구분선(━━━)은 출력물에 넣지 않음 — 위 포맷의 `---`는 댓글 구분 표시용

## 4. 콘텐츠 유형별 템플릿

### A. 뉴스/소식 전달형
```
[도발적 헤드라인]
[핵심 한 줄]

1 / N

---

[배경 + 세부 내용]
[왜 중요한지]

2 / N

---

[한줄평 or 의견]
[출처 링크]

N / N
```

### B. 도구/서비스 소개형
```
[도구명] — [한 줄 설명]
+) [추가 가치: 무료, 꿀팁 등]

1 / N

---

[사용법 or 핵심 장점]
[구체적 예시]

2 / N

---

[링크]
[CTA]

N / N
```

### C. 투표/참여형
```
[상황 설정]
[A vs B]
스친들 선택은?

1 / 1~2
```

### D. 일상 관찰/에피소드형
```
[현장 상황 묘사]
[관찰 포인트]

1 / N

---

[전개 + 디테일]
[펀치라인 or 감상]

N / N
```

### E. 동기부여/에세이형
```
[도발적 첫 문장]

1 / N

---

[개인 경험 나열]
[짧은 단문 연속]

2 / N

---

[결론: 직설적 한 줄]

N / N
```

### F. 가이드/리스티클형
```
[제목 + 긴급성/가치]
댓글에 공유하겠습니다

1 / N

---

1/
[첫번째 방법]
[구체적 설명]

2 / N

---

2/
[두번째 방법]
[구체적 설명]

3 / N
```

**리스티클 주의**: 슬라이드 안에서 `1/`, `2/` 서브 넘버링 가능

## 6. 출처/링크 처리

- **본문에 링크를 넣지 않는다** — 본문에는 사진 또는 동영상을 첨부
- 출처 링크는 **마지막 댓글에만** 배치
- 짧게: `anthropic.com/news…` (URL 뒤에 `…` 붙여서 축약)
- 사이트명만 써도 OK: `Perplexity`, `LMARENA`
- **공식 원본 우선**: 뉴스 기사가 아닌 공식 블로그/문서/공지를 1순위로 넣을 것
  - 예: aitimes.com 기사가 아니라 anthropic.com/news/... 공식 블로그를 넣어라
- **영어 원문 필수**: 한국 뉴스 번역본이 아니라 영어 원문 기사를 찾아서 링크할 것
  - 검색 시 영어 키워드로 원문 검색 → 공식 블로그 > 영문 1차 보도(TechCrunch, VentureBeat 등) > 한국어 기사 순
  - 예: 연합뉴스 번역이 아니라 jpost.com 원문, 중앙일보가 아니라 venturebeat.com 원문

## 6-1. 미디어 첨부 (사진/동영상)

### 본문에 넣을 미디어
- 뉴스 기사의 대표 이미지, 스크린샷, 제품 화면 등을 직접 다운로드하여 저장
- 기사 원문에서 핵심을 보여주는 이미지를 선택
- 동영상이 있으면 함께 저장 (공식 발표 영상, 데모 영상 등)
- 미디어를 확보할 수 없으면 `(미디어 필요)` 태그를 본문에 남겨 유저가 직접 추가하도록 유도

### 미디어 확보 방법 (우선순위)
1. 기사 원문의 대표 이미지 URL → `curl -sS -L -o cover.jpg` 로 직접 다운로드
2. 원문 이미지 확보 실패 시 → **Google Images 검색**으로 관련 이미지 다운로드
   - 검색 키워드: 기사 핵심 인물/제품/회사명 (영문)
   - `tbm=isch` 파라미터로 이미지 검색, 또는 브라우저로 Google Images 접근
   - 저작권 주의: 뉴스 보도 목적의 fair use 범위 내에서 사용
3. `curl -sS -L -o` 로 이미지 직접 다운로드하여 폴더에 저장
4. 다운로드 후 반드시 `file` 명령으로 실제 이미지인지 검증 (HTML이면 재시도)
5. 파일명 규칙: `cover.jpg`, `cover.png`, `screenshot_1.png`, `demo.mp4` 등 내용 알 수 있게
6. 모든 방법 실패 시 → `(미디어 필요)` 태그 남김

## 7. 입력 처리

### 🔍 사전 검색 (MANDATORY)
**쓰레드 작성 전 최소 2회 웹 검색 필수.**
최신 정보를 기반으로 써야 신뢰도가 올라간다.

```
1회차: 주제 키워드 검색 → 최신 상황 파악
2회차: 관련 수치/팩트 검색 → 구체적 숫자 확보
```

검색 없이 기억에 의존해서 쓰면:
- 날짜/버전/가격이 틀릴 수 있음
- 이미 바뀐 정보를 쓸 수 있음
- 댓글에서 팩트체크 당하면 신뢰 끝

### 입력 유형별

| 입력             | 처리                                                 |
| ---------------- | ---------------------------------------------------- |
| URL              | 내용 요약 → 쓰레드 변환 (`summarize` 스킬 연계 가능) |
| 주제만           | **검색 2회** → 최신 정보로 작성                      |
| 텍스트           | 쓰레드 형식으로 재구성                               |
| 뉴스 + 의견 요청 | **검색 2회** → 팩트 확인 → 마지막에 가벼운 의견      |

**검색 언어**: 영어 키워드로 원문 검색을 기본으로 하고, 한국어로 추가 검색. 원문 기사 링크를 확보하는 것이 목표.

### 유저 옵션
- `N장으로` → 슬라이드 수 지정
- `진지하게` / `가볍게` → 톤 조절
- `후킹 강하게` → 훅에 집중
- `링크 빼줘` → 출처 생략

## 8. 자체 검증 (생성 후 반드시 수행)

1. **후킹**: 첫 슬라이드가 3초 안에 "뭔데?" 반응을 유발하는가? (실패 시 리라이트 공식으로 재작성)
2. **톤 일관성**: 반말이면 끝까지 반말인가? 존댓말이 섞여 있지 않은가?
3. **자연스러움**: AI가 쓴 것 같지 않은가?
4. **길이**: 부풀리지 않았는가? 핵심만 있는가?
5. **번역체**: "~에 대해", "~를 통해" 같은 표현이 없는가?
6. **줄바꿈**: 마침표 대신 줄바꿈을 사용했는가?
7. **정보 격차**: 다음 슬라이드를 안 넘길 수 없게 만들었는가?
